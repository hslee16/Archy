## SEVERITY 4 — The run-order confound is real and measurable, and is not the admitted breadth confound

`run_pair` (`agent_footprint.py:436-437`) always iterates `("A", …), ("B", …)` — A is never second. The writeup calls this "interleaved" (`:134`), which covers *between*-pair drift but not *within*-pair order.

The data shows a one-sided drift. Spearman vs `run_index`:

| series | rho |
|---|---|
| A `pre_edit_reads` | **+0.782** (past the n=10 0.05 critical value of ~0.648) |
| B `pre_edit_reads` | +0.248 |
| A `num_turns` | +0.491 |
| B `num_turns` | −0.055 |

A's reads climb 7 → 13 across the run; B's are flat. Since A always ran first, variant and within-pair position are perfectly confounded, and the drift inflates the B-favorable direction of the metric of record. It does not flip the conclusion (first-5 median Δ = −3, last-5 = −4, both negative), but the writeup's "direction favors B" is partly a position artifact and the asymmetry is unexplained. Counterbalancing order (A/B on even pairs, B/A on odd) is a one-line fix for the next run.

## SEVERITY 5 — Selective reporting: Bonferroni over 9, table shows 6

The Bonferroni divisor of 9 is **correct** — `summarize()` at `agent_footprint.py:524-534` tests exactly 9 metrics. But the results table (`:151-158`) shows only 6. ## SEVERITY 6 — `records.jsonl` append: no dedup, and `_paired_deltas` silently drops collisions

`agent_footprint.py:411-412` appends unconditionally, never truncates. The stated purpose (`:407-410`) is crash durability. But the recovery path is broken:

- A re-run into the same `--out` restarts `run_index` at 0, producing duplicate `(variant, run_index)` keys in the file.
- `_paired_deltas` (`agent_footprint.py:504-506`) does `by_run.setdefault(r.run_index, {})[r.variant] = r` — **last write wins, silently**. Reconstructing a topped-up run from the JSONL therefore discards the earlier rows with no warning and no `n_pairs` mismatch to notice.
- `_main` also writes `records.json` (`:626`) from the in-memory list, so the two artifacts disagree after any resume.

The committed `records_282_flask.jsonl` is clean (20 rows, indices 0-9 × A/B, no dupes), so this did not affect *this* result. But the durability feature the PR advertises does not actually survive being used.

Related, lower: after the last run the repo is left dirty, since `_reset_repo` runs *before* each run and never after.

## SEVERITY 7 — A red baseline is silently unrecorded, so "0 regressions" is not falsifiable from artifacts

`_run_test_gate` returns `False` when `baseline_failed` is True (`agent_footprint.py:315`), with the docstring noting "the caller should flag it" — **no caller flags it**. `FootprintRecord` has no `baseline_failed` field, so it is absent from all 20 rows. `summarize()` counts `regressions=0` either way.

Result: nothing in `records_282_flask.jsonl` distinguishes "suite green after the agent's edits" from "baseline was red so the gate was disabled." The writeup's "491/491 green on both pristine variants" (`:135`, `:145`) and "all 10 admissible… 0 regressions" (`:148-149`) are therefore assertions, not artifacts. Add `baseline_failed` to the record, or raise when a baseline is red.

## SEVERITY 8 — `git clean -fdx` deletes the isolation mechanism it depends on

`_reset_repo` (`agent_footprint.py:315-316`) runs `git clean -fdxq`. `-fd` removes untracked **directories** regardless of ignore status, so any `.claude/` inside the variant repo is deleted before every run. Spec §10 and `_run_claude`'s docstring (`agent_footprint.py:277-280`) describe `--setting-sources local` as "only the project's own settings load" — from this PR onward there are no project settings left to load by the time `claude` starts. Benign-to-beneficial here (more isolation, not less), but it is a silent behavior change relative to how #289 ran and relative to how the spec describes the isolation, and it should be documented.
