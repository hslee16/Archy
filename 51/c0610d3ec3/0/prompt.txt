**Crash**

**Lost links against main (real installed packages)**

2. **Optional override that cannot be followed drops the working definition** (high realism).
   - `try: from ._speed import Base` / `except ImportError: from ._py import Base`, where `_speed` is a C extension, gives no link. The runtime fallback is `_py.Base`.
   - `wrapt` has a variant: a pure-Python import first, then `if ...: try: from ._wrappers import ...` overrides it. 82 of 105 family memberships are gone, including the whole `FunctionWrapper` and `CallableObjectProxy` families.
   - Possible fix: do not let a target in a nonexistent internal module replace, or block, a followable one.
3. **Rebinding a class name by a call** (moderate). `gunicorn/config.py` does `Setting = SettingMeta('Setting', (Setting,), {})`. The name becomes `None`, so the 120-member `Setting` family disappears entirely. Linking to the original class would be correct.
4. **Absolute imports that omit the scanned prefix** (documented limit, but larger than it reads).
   - Running on the `poetry` package directory (a namespace package) loses the `Command` family (46 members).
   - Sibling-script imports (`from fusion_base import Fusion`) lose 67 bases in `onnxruntime`; `debugpy`'s vendored `pydevd` is similar.
   - A `backend/app` layout with `from app.b import Base` still works.
