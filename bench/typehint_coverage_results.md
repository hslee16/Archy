# Type-hint coverage on the 27-project bench

Generated by `bench/typehint_coverage.py` against the 27 projects pinned in `bench/projects.yaml`. Captured 2026-05-16. Companion analysis in `research/product/typehint-coverage-analysis.md`.

Coverage = annotated_positions / total_positions over public functions. A position is a parameter (excluding `self`/`cls`) or the return slot. A function is "public" if its name does not start with `_`, with the exception that dunders (`__init__` etc.) are counted as public.

## Pearson r against the existing 5 axes

Lower absolute value = more orthogonal. OECD redundancy threshold = `|r| > 0.7`.

| axis | r vs coverage |
| --- | ---: |
| modularity | -0.511 |
| acyclicity | -0.542 |
| depth | +0.551 |
| equality | +0.037 |
| complexity | -0.030 |

Three of the five correlations sit at the boundary of OECD "moderate coupling" (`|r|` 0.5-0.7); the highest absolute value is +0.551. The bench thus does *not* show the same dramatic-orthogonality picture that justified `complexity`'s v0.20 promotion (max `|r| = 0.197`).

## Distribution shape

Sharply bimodal:

- **Typed (coverage > 0.85)**: 15 projects. Mature modern libraries that adopted typing as an explicit policy. mypy and pydantic at the top of this band are unsurprising (mypy eats its own dogfood; pydantic's whole value proposition is typed validation).
- **Partial (0.50-0.85)**: 4 projects. pytest, dagster, mkdocs, sqlalchemy. Mid-transition.
- **Untyped (< 0.20)**: 7 projects. django, boto3, botocore, pygments at literal zero; numpy, scikit-learn, datasette just above.

This is a *temporal* distribution as much as a quality distribution. django moving toward types (gradual progress since the 4.x line), numpy partially typed via stubs, boto3 generated code mostly untyped. The bottom of the bench will look very different on a 2028 run.
