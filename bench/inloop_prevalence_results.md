# In-loop prevalence study results

Generated by [`bench/inloop_prevalence.py`](inloop_prevalence.py). Full analysis and interpretation
in [`docs/research/INLOOP_PREVALENCE_EMPIRICS.md`](../docs/research/INLOOP_PREVALENCE_EMPIRICS.md).
Raw rows: [`inloop_prevalence_results.json`](inloop_prevalence_results.json).

**Question:** how often does a single real human-authored commit introduce a structural regression
archy is built to catch (new import cycle / score drop)? This is the prevalence base rate behind the
"does archy-in-the-loop reduce structurally-bad edits?" open question.

**Corpus:** 1,072 single-parent commits sampled across history in 11 mature Python repos (click,
requests, flask, httpx, starlette, rich, pydantic, fastapi, scrapy, mkdocs, datasette). Package dir
per repo per `projects.yaml`; metrics via archy's own `build_graph` + `compute_score`.

## Key numbers

- New import cycle introduced: **0.5%** of commits (5/1072), stable vs the N=360 pilot (0.6%).
- Cycle-introducing commits are large: **median 7 `.py` files changed vs 1** for all other commits.
- New tangles are multi-module: newly-formed SCC size min 2, median 3, max 8; only 1 of 5 was a trivial 2-module cycle.
- Score drops are common but trivial: **98% of the 315 drops were < 0.005** (median ≈ 0, worst -0.0197).
- Size regime: median commit touches 1 `.py` file; only 2.1% touch ≥10.

## Reproduce

```bash
uv run python bench/inloop_prevalence.py --per-repo 100 --out bench/inloop_prevalence_results.json
```

Clones land in `bench/replay_cache/` (gitignored). Sampling anchors to each repo's default-branch
tip, so reruns are independent of any detached HEAD a prior run left behind.
